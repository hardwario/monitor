The fourth release candidate of **HARDWARIO Monitor**, the console, log and flashing tool for HARDWARIO CHESTER, as a desktop app for Windows, macOS and Linux and as the command-line tool `hwio`. It builds on 2.0.0-rc.3 and adds remote support and user modes.

This is a pre-release for testing. Please report problems in [Issues](https://github.com/hardwario/monitor/issues); `hwio diag report` (or **Help › Create diagnostic report…** in the app) creates a report you can attach. HARDWARIO Monitor version 1 stays available and can be installed side by side until version 2 replaces it.

## What is new since 2.0.0-rc.3

**Remote support**
- **Share with support…** on the Console page shares the console of a J-Link or Bluetooth device with HARDWARIO Support. You read a 6-digit code to support over the phone; it works with the [HARDWARIO Terminal](https://terminal.hardwario.com/) server, so support can join from the web Terminal or from HARDWARIO Monitor.
- Every join asks you first (**End session** is the default); commands from support are marked in the console. Support using HARDWARIO Monitor can ask to flash catalog firmware, erase, recover or reset the device, and each request needs your click (**Deny** is the default).
- Support can also ask to update the LTE firmware to the version your HARDWARIO Monitor recommends. After you allow it, **Flash › Update LTE firmware…** opens with that firmware and guides you through moving the J-Link cable; support sees each step and the result, and sharing stays on while the device reconnects.
- Support's console completes commands (suggestions and Tab) from the command list your HARDWARIO Monitor has learned; the help it reads for that is not shown in your console.
- **Join support session…** on the **Choose a device** page joins a session shared from HARDWARIO Monitor or from the web Terminal.
- Anyone who knows the code sees the console output, even before you allow them; read the code only to HARDWARIO Support. Every join, remote command and operation is written into the console file. See [Remote support](https://github.com/hardwario/monitor/blob/main/docs/en/remote-support.md).

**User modes**
- **Settings › General › Mode** chooses how much the app shows: **Basic** (watch the console and flash firmware; only the essential settings), **Advanced** (develop with CHESTER: J-Link and nRF Util options, AI assistants, console tools) or **Expert** (full control, including the timing options and the maintenance actions that can erase the device's identity). A hidden setting keeps its value and is still used; an error that needs a hidden setting opens it for that visit. See [Modes](https://github.com/hardwario/monitor/blob/main/docs/en/getting-started.md#modes).
- At the first start, and once after updating from rc.3 or older, the app asks **How do you want to use HARDWARIO Monitor?** with **Advanced** preselected (**Expert** if you had **Show expert maintenance actions** on). Closing the dialog keeps the preselection.
- **Erase everything…**, **Recover…** and the LTE MCU maintenance on the Flash page are now part of the Expert mode; the switch **Show expert maintenance actions** is gone, and the Settings section **Advanced** is now called **Expert**.

**Also**
- Bluetooth: the arrow keys move through the device list; Down in the filter enters the list.
- Settings › AI assistants (MCP): clicking the permission that is already selected keeps it selected.

## Command line and scripts

- New `hwio remote host` (J-Link, or `--ble`) shares a console and asks on the terminal before it allows a join or an operation; without a terminal on stdin it ends at the first join. `hwio remote join CODE` joins a session: the console, one `--command`, or a `--flash ID` / `--erase` / `--recover` / `--reset` / `--lte-update` request. An allowed LTE update runs the terminal flow of `hwio chester lte flash --guided` on the host. The interactive `remote join` console completes commands from the host's command list. Both support `--json`.
- New error codes `remote.*` (see Troubleshooting); a join or an operation the customer did not allow exits with code 130.

## Known limitations of this release candidate

- Remote support: a web Terminal customer offers support the console only (no flash, erase, recover or reset). The session code is guessable, which is why the console output is visible to anyone with the code but commands always need your approval.
- A plain `hwio chester lte flash` (without `--guided`) can fail while the application firmware is running, because it may reset the LTE MCU during the update; `hwio` warns about this. Use `hwio chester lte flash --guided` or **Flash › Update LTE firmware…**, which stop the application first.
- The guides for connection troubleshooting, first-run setup and flashing come in a later release candidate.
- nRF Util is not installed by the app yet; follow the steps behind **How to install ↗**.
- `hwio chester app halt` halts the CPU only while the command runs; it is running again after the command exits.
- The app does not update itself; install a newer version over the old one, settings are kept.
