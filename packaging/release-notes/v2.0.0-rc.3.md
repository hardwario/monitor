The third release candidate of **HARDWARIO Monitor**, the console, log and flashing tool for HARDWARIO CHESTER, as a desktop app for Windows, macOS and Linux and as the command-line tool `hwio`. It builds on 2.0.0-rc.2 with the feedback from its first users.

This is a pre-release for testing. Please report problems in [Issues](https://github.com/hardwario/monitor/issues); `hwio diag report` (or **Help › Create diagnostic report…** in the app) creates a report you can attach. HARDWARIO Monitor version 1 stays available and can be installed side by side until version 2 replaces it.

## What is new since 2.0.0-rc.2

**LTE firmware update, guided**
- **Flash › LTE firmware › Update LTE firmware…** opens a step-by-step guide: it saves a copy of the application, stops it, tells you when to move the J-Link cable between the APP and LTE connectors (and notices when you did), updates the LTE MCU and writes the application back. This removes the random LTE flashing failures caused by the running application.
- App or LTE is no longer chosen on the Choose device page; a tab always works with the application MCU. When the J-Link is on the LTE connector, the tab says so and offers **Update LTE firmware…**.
- Easier nRF Util installation: short per-system steps in the documentation, and **Download nRF Util ↗** next to **How to install ↗** wherever the app needs nRF Util.
- When an LTE update fails because the application firmware on the APP MCU reset the LTE MCU, the app now says so and points you to the guided update, instead of a generic programming error.

**AI assistants in the desktop app**
- The app can run an MCP server for AI assistants (**Settings › AI assistants (MCP)**, off by default, localhost only). The assistant works with the devices in your open tabs, including Bluetooth tabs; a consent window asks you before it connects, flashes or erases, and its activity is shown in the console and in Settings.

**J-Link probe firmware**
- When the probe firmware is outdated, the warning on the tab offers **Disconnect and update…**: the app updates the probe firmware and shows the progress and result. It is not offered while a flash, an LTE update, Diagnose or an AI operation uses the probe.

**Also**
- User interface in **German, Slovak and Polish**, in addition to English and Czech.
- **Learn more** on every error and links from Help and the guides open the matching page of the documentation, in your language and for your version of the app.
- Bluetooth: the device list no longer jumps under the pointer; it is ordered by a smoothed signal strength and holds still while you point at it.
- **Erase everything**, **Recover** and LTE MCU maintenance are hidden by default; turn on **Settings › Advanced › Show expert maintenance actions** to see them. Erase application is always available.
- Settings opened from an error or a guide now scrolls to the right section.
- The product name is **HARDWARIO Monitor** everywhere, with a new application icon.

## Command line and scripts

- New `hwio chester lte flash --guided`: the same guided LTE update in the terminal. It ends with **exit code 130** when the LTE MCU was updated but no copy of the application could be written back (the application MCU is empty); exit code 0 means a complete update.
- **Breaking for scripts:** `hwio ble scan --json` renames the key `rssi_last` to `rssiLast`, like all other keys of the output.
- The debug symbol archives are now named `hwio-monitor-2.0.0-rc.3-debug-symbols-<system>.zip`.

Then run `hwio doctor` or start the app: [Installing](https://github.com/hardwario/monitor/blob/main/docs/en/install.md) · [Getting started](https://github.com/hardwario/monitor/blob/main/docs/en/getting-started.md).

- **Linux AppImage:** install the J-Link udev rule yourself (see Installing).
- The `debug-symbols` archives are for crash analysis; you do not need them.

**Verify a download:** `sha256sum -c SHA256SUMS --ignore-missing`, or `gh attestation verify <file> --repo hardwario/monitor` (build provenance from GitHub Actions).

## Known limitations of this release candidate

- A plain `hwio chester lte flash` (without `--guided`) can fail while the application firmware is running, because it may reset the LTE MCU during the update; `hwio` now warns about this. Use `hwio chester lte flash --guided` or **Flash › Update LTE firmware…**, which stop the application first.
- The guides for connection troubleshooting, first-run setup and flashing come in a later release candidate.
- Tested on real CHESTER hardware on Linux; the manual checks on Windows and macOS are still running, also for the new LTE update guide, the probe firmware update and MCP in the app.
- nRF Util is not installed by the app yet; follow the steps behind **How to install ↗**.
- `hwio chester app halt` halts the CPU only while the command runs; it is running again after the command exits.
- The app does not update itself; install a newer version over the old one, settings are kept.
